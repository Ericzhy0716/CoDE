这是CoDE-Stop的独立复现与后续研究项目，创建于2026-09-20，由[Ericzhy0716/CoDE](https://github.com/Ericzhy0716/CoDE)维护。后续相关代码、配置、实验记录和分析统一放在这里。它与此前研究独立；旧研究资料保留为历史记录。

```text

├── README.md                  项目入口与当前状态

└── results/                   整理后的指标、图表和实验报告
```

**当前状态**

已建立独立目录，收纳复现要求、创新可行性、费用与API方案说明和官方代码参考副本。现有 `scripts/single_question.py`、`configs/single_question.json` 和 `src/` 单题诊断封装，可分阶段保存、恢复和独立教学判分。尚未在此目录启动GPU实验，也没有将官方代码/论文差异处理完毕；本地工程检查不等于真实模型验证。当前目标为COLING2027冲刺：先完成单题闭环及有限价值诊断，再按证据决定扩大范围。

每次正式实验需保存代码版本、配置、模型和数据版本、样本划分、随机种子、判分方式及完整性核验；论文报告的token成本与实测运行时间分别记录。官方代码原样运行、论文公式对齐版本和新方法实验需分开标记。

**当前协作方式：用户主导完整复现过程（2026-09-21）**

用户希望亲自完成更多操作，理解从准备到结果分析的全过程。后续以小步教学推进：每一步说明目的、执行位置（Mac或服务器）、命令/代码含义、预期结果和检查方式；用户执行后，助手依据实际输出协助解释与排错。实验操作默认交给用户，助手继续协助代码审阅、预算核验和经核验文档的Git同步；用户明确交办的具体操作可由助手完成。

学习顺序：认识项目结构与实验输入输出 → 环境及模型检查 → 单题完整生成与判分 → 单个检查点的试答和置信度 → DEER/CoDE停止决策 → 独立开发/校准与完整子集评测 → 统计分析和候选创新验证。先弄清单题流程，再使用批处理脚本。

第一个学习目标是在现有Mac目录中辨认官方代码、我们自己的代码、配置、原始记录和结果报告的位置，并理解Vanilla、DEER、CoDE共用基础轨迹但采用不同停止决策。目录准备不需要GPU；模型运行的资源安排沿用实验优先级和预算文档。阅读顺序、精略程度与代码对照将在相应步骤给出，不要求先通读所有资料。

**获取项目**

```bash
git clone --recurse-submodules https://github.com/Ericzhy0716/CoDE.git
```

已经克隆但未获取官方代码时，在仓库根目录运行：

```bash
git submodule update --init --recursive
```

上述命令只获取代码；不会安装依赖、下载模型或启动实验。上游环境文件仍为原始示例，需要按复现要求单独配置。
