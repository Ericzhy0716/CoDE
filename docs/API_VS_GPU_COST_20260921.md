# API 与低价单卡：同一实验的费用比较

核查日期：2026-09-21。只做公开价格查询、原代码显存静态分析和离线算术；没有开机、购买或付费推理。本文不声称已找出全市场最低价或已实测最低总成本。

## 当前决策

用户希望使用论文中的Qwen及DeepSeek模型。若保持原检查点、BF16精度和实验协议，当前可明确控制实现的是租卡自行部署；现有便宜API候选仍需能力验证，且已核实的DeepInfra Qwen3-14B为FP8，不能无说明替代BF16。API的条件预算不能充当已经找到兼容服务的报价。

**先将1张RTX 5090 32GB作为Qwen3-4B首轮的低价测速候选，公开参考价2.78元/小时。** 这不是保证它足够或最便宜。原样长前缀显存峰值和端到端耗时必须测过；失败后优化内存实现或提高显存，不能缩短32K预算、量化或换模型却仍称原条件复现。

此前按PRO6000 96GB、6.98元/小时估算的GPU费用代表较宽裕配置，不能用它代表最经济的租卡方案。另一方面，低时租不保证低总费用，取决于同一实验完成速度。

## 2. 什么显存值得尝试

下面是batch=1、32,768总上下文、BF16的一份KV缓存和全前缀logits的静态量级，**不是实测峰值或最低显存**。论文要求32K新生成，实际加输入后上下文更长；原代码的激活、注意力临时量、CUDA、缓存复制及CPU内存都需额外空间。

| 原模型 | 权重 | 单份KV | 全前缀BF16 logits | 三项小计 |
| --- | ---: | ---: | ---: | ---: |
| Qwen3-4B | 7.49GiB | 4.50GiB | 9.27GiB | 21.27GiB |
| DeepSeek-R1-Distill-Llama-8B | 14.96GiB | 4.00GiB | 7.83GiB | 26.79GiB |
| Qwen3-14B | 27.51GiB | 5.00GiB | 9.27GiB | 41.78GiB |

依据固定代码的[模型加载](https://github.com/sudoparsa/CoDE-Stop/blob/b5081e7c2abe23bb1d19649421cc13522fee7c50/models.py)、[CoDE直接前向](https://github.com/sudoparsa/CoDE-Stop/blob/b5081e7c2abe23bb1d19649421cc13522fee7c50/method_codestop.py)和各原模型配置。`cp_cache=False`的全前缀forward没有限制只输出末尾位置logits；`cp_cache=True`涉及CPU/GPU搬运及缓存副本。适当限制不需要的logits或分块前缀计算可能省显存，但属于须验证一致性的工程修改。

配置与权重体积可由[Qwen3-4B配置](https://huggingface.co/Qwen/Qwen3-4B/blob/main/config.json)及[权重索引](https://huggingface.co/Qwen/Qwen3-4B/blob/main/model.safetensors.index.json)、[DeepSeek8B配置](https://huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Llama-8B/blob/main/config.json)及[权重索引](https://huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Llama-8B/blob/main/model.safetensors.index.json)、[Qwen3-14B配置](https://huggingface.co/Qwen/Qwen3-14B/blob/main/config.json)及[权重索引](https://huggingface.co/Qwen/Qwen3-14B/blob/main/model.safetensors.index.json)复核。

原代码缓存模式的常驻缓存及deepcopy起点位于CPU，不能机械地加算两份GPU KV；CPU内存和传输速度同样重要。标准`generate`在相应实现中会限制末位置logits，不等同于手写全前缀forward的峰值。上述全前缀logits没有再额外计一块FP32 softmax，CoDE只对末token位置的向量计算概率。[Transformers 4.51.3实现](https://github.com/huggingface/transformers/blob/v4.51.3/src/transformers/models/qwen3/modeling_qwen3.py)

选择建议：

- **4B：32GB先测；24GB只有在长样本峰值验证通过后再考虑。** 不能因权重仅8GB就保证24GB能运行原协议。
- **8B：32GB作为待测候选，48GB有更多余量。** 价格最低的24GB卡不适合作为原样32K复现的默认保证。
- **14B：48GB可作为待测候选；若不优化原实现或长样本峰值过高，再用80GB。** 32GB不能仅靠装入权重就视为可用。

## 3. 比较口径

以Qwen3-4B、MATH500、每题2次、Vanilla+DEER+CoDE三方法为同一任务。完整基础轨迹只生成一次供方法共享。API探测的输入/输出、平均前缀等假设沿用[API预算文档](API_TOKEN_BUDGET_20260921.md)。

费用比较必须使用同模型、精度、输出预算、采样、判分和方法覆盖。**不能直接用FP8 Qwen14B的API价格与BF16 Qwen4B租卡费用，得出同一实验谁更省。** 量化部署研究可单独比较，但不是原条件复现。

共同判分费在对等比较中可相消；下面暂不计存储与支付手续费。租卡时间T必须是总计费时间，包含GPU开机期间的加载、前缀计算、生成、缓存搬运和空闲等待。可以在本地或无GPU阶段完成的准备不必计入GPU时间。

```text
GPU费用 = 每小时租价 × 总计费小时 + 额外存储等费用
API费用 = 总输入百万token × 输入价 + 总输出百万token × 输出价
租卡盈亏平衡小时 = 对等API费用 ÷ 每小时租价
```

## 5. 大规模或反复实验不自动使租卡更便宜

两种方案通常都随样本量增长。决定翻转点的是有效吞吐、GPU利用率、每题探测次数、API重复输入计费及双方缓存复用，而不是单纯“实验多就租卡便宜”。

- 5090时租是4090的约1.48倍。两者都能运行时，5090整套吞吐需超过4090约48%，才更省租费。
- 4090时租是3090的约1.42倍；超过约42%的吞吐增益才抵消时租差。
- PRO6000时租是A800的约1.25倍；超过约25%的吞吐增益才更省。
- 若只修改停止阈值，而且已有足够的完整轨迹、试答概率和最终答案缓存，优先在Mac回放分析，双方都可能无需重复生成；若新的停止点或试答未缓存，则仍需补算。

不能用纸面FP16算力替代上述真实端到端吞吐，尤其此代码有大量小步生成、全前缀计算与缓存搬运。

## 6. 最小决策实验

当前建议是为4B预留 **1小时5090诊断预算，按公开参考价约2.78元，另计存储**。这是建议额度，本次没有购买或运行，也不保证一小时完成所有准备和长样本。

先在本地准备依赖、脚本、固定题目与计时记录；开机后检查短、中、长输入及高探测次数样本的峰值显存，记录基础生成、试答、最终答案与缓存开销。用真实耗时和探测次数外推本表，再选择批量租卡或经能力验证的API。调环境超时就先报告，不将预算建议当成已授权连续开机。

在没有可用原模型API报价、没有GPU端到端测速之前，结论是：**低价单卡已具备与API竞争的费用区间；当前不能证明API一定更便宜。对保持原模型协议的研究，5090是值得先验证的候选，而非已证实的全局最优。**
