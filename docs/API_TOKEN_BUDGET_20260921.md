核查日期：2026-09-21。本次仅查询公开价格和接口说明、运行离线预算计算；未购买服务、调用付费推理API或租用GPU。本文补充[此前的费用与可行性说明](COST_AND_API_FEASIBILITY_20260921.md)。

## 1. 方案含义

“本地部署 + API”在本文指：实验代码、数据处理、结果和绘图位于现有Mac，模型推理由API供应商承担。新增服务器/GPU租费为0，不需要购买新电脑；未计已有电脑折旧、网络、电费与研究人工。

若改为Mac本地运行一部分模型，只有实际移到本地的推理调用可从API费用中扣除。不能用本地量化小模型计算另一个远端模型的置信度，却仍称为原始CoDE；同一条轨迹的生成和探测应使用一致、可记录的模型配置。离线阈值分析和已缓存结果重算可在Mac完成，无需重复付费生成。

## 3. 统一测算范围

估算 Vanilla、DEER、CoDE三种方法，共享一份完整基础轨迹；两个停止策略的探测暂不共享缓存。估计的是**基于完整轨迹的回放实验账单**，不是在线早停后的真实账单或加速比。

MATH500：500题，每题2次，共1,000条基础轨迹/模型。四主要基准：4,209条/模型。[规模和平均输出来源](https://arxiv.org/html/2604.04930v2)。

| 模型 | MATH500基础输出 | 四基准基础输出 |
| --- | ---: | ---: |
| Qwen3-4B | 5.210百万token | 32.385654百万token |
| Qwen3-14B | 4.878百万token | 29.063922百万token |
| DeepSeek-R1-Distill-Llama-8B | 4.576百万token | 29.103090百万token |

这些来自论文取整后的均值，不是我们或API端点的实际生成长度；量化服务可能改变长度。

额外假设：每条题目及模板500token；每次试答平均重发基础推理长度的一半；追加提示20token；试答最多21token；最终答案预留30token；基础完整输出额外预留一次强制答案，每种停止方法也各预留一次最终答案。按每条轨迹、每种策略平均 **5次或20次** 探测测算，另给100次的高频情景。探测次数和平均前缀均未实测，不能把5–20当作原论文公布值。

令N为轨迹数、L为平均基础输出、K为每策略探测次数、p=500、H=20、S=2、A=21、F=30，则：

```text
输入token = N × [p + (p+L+H) + S×(K+1)×(p+L/2+H)]
输出token = N × [L + F + S×(K×A+F)]
请求次数 = N × (2K+4)
token费用 = 输入token/百万 × 输入单价 + 输出token/百万 × 输出单价
```

不计缓存优惠，也未计失败重试、AMC校准、判分、开发诊断、其他基线和消融。已正确输出的基础答案若无需强制重答，可省掉该预留；相同试答能够共享缓存时，也能降低费用。

将上述假设套入DeepInfra公开价格，仅估token账单：

| 范围 | K=5 | K=20 | K=100（高频情景） |
| --- | ---: | ---: | ---: |

| Qwen3-14B，四主要基准，三方法 | **254.58元** | **692.57元** | **3,028.46元** |

在K=5–20情景下，MATH500加约30%预算余量与20元杂项预留，约78–180元；建议首轮准备 **100–200元**。这不是完成保证，FP8、协议及32K输出支持须先验证。若该端点只能生成更短输出，不能悄悄缩短原实验预算。

按百炼北京Qwen3-14B思考模式单价做纯计价对照，同一MATH500规模为约93–188元；该接口的功能限制不能由费用计算消除，因此不将它作为已确定复现方案。

## 5. 用户原定Qwen4B + DeepSeek8B的条件预算

这两个具体模型尚未核实兼容现价，故以下**不是供应商报价**。为便于决定研究规模，设两个可选单价情景（元/百万token）：

- 较低价情景：输入0.5、输出2。
- 较高价情景：输入1、输出3。

| 范围 | 较低价：K=5–20 | 较高价：K=5–20 |
| --- | ---: | ---: |
| Qwen3-4B，MATH500，三方法 | 33–81元 | 60–156元 |
| DeepSeek8B，MATH500，三方法 | 29–73元 | 54–140元 |
| **两模型MATH500合计** | **62–154元** | **114–296元** |
| **两模型四基准合计，仍仅三方法** | **374–911元** | **684–1,753元** |

若能找到兼容接口且单价处于上述情景内，加入约30%预算余量及额外预留后：

- 两模型MATH500首轮可暂留 **150–450元**。
- 两模型四主要基准可暂留 **550–2,400元**；这仍非全文所有基线和消融。

以上是假设K=5–20的规划范围，不是概率区间或上界。若平均探测达100次，两模型MATH500仅token费用就约642–1,265元。题目更长、探测集中在后段、参数反复重跑或失败重试，都会提高成本；共享试答缓存和命中供应商前缀缓存可能降低成本。

MATH500单模型约需14,000–44,000次请求（K=5–20），因此费用低不等于当天能完成；须测限流、每请求延迟、长上下文和重试率。

## 6. 执行顺序

1. 在Mac完成适配层与日志准备；当前不需要先开GPU实例。
2. 先给API能力诊断设置 **20–50元支出上限**，只测试少量题。该金额是预算上限，不是平台最低充值额，也未实际花费。需要验证raw前缀、greedy概率语义、完整推理及32K预算组合。
3. 通过后记录一次短、中、长轨迹的实际usage、探测次数和耗时，替换本预算假设，再开展有边界的MATH500比较。若采用FP8或换模型，先写入实验协议，不与BF16结果混合报告。
4. 如果回放缓存齐全，先在本地分析阈值和失败案例，再决定哪些配置必须重新推理，避免每调一个参数就全部重跑。

## 7. 可复算的离线工具

[estimate_api_budget.py](../scripts/estimate_api_budget.py)仅计算费用，不读取密钥、不联网、不调用模型。价格必须显式输入，程序不会自动声称某平台兼容。

例如按本日DeepInfra标准价格与预算汇率计算：

```bash
python3 scripts/estimate_api_budget.py \
  --model qwen3-14b --scope math500 \
  --input-price-cny 0.864 --output-price-cny 1.728
```

输出包括探测次数情景、输入/输出量、请求数及纯token费，不自动加预算余量。`--prompt-tokens`、`--prefix-fraction`与`--checks`可用实测值替换默认假设。
