# CoDE-Stop：费用与 Mac/API 可行性

日期：2026-09-21。本文为静态审查与预算情景，未进行 GPU 测速或付费 API 实验。

## 结论

原方法不需要训练；Mac 可以负责数据准备、接口调用、日志、统计和绘图。若托管接口支持精确的生成控制和 token 概率，理论上可以用 API 完成相应方法实验。但目前没有核验任何供应商满足全部要求，不能保证普通聊天 API 可以直接替代官方实现。

用户希望使用论文中的千问和 DeepSeek。这里必须区分具体模型：Qwen3 的主要实验型号为 `Qwen/Qwen3-4B`、`Qwen/Qwen3-14B`；DeepSeek 型号为 `deepseek-ai/DeepSeek-R1-Distill-Llama-8B`。不能把任何同品牌聊天接口当作上述检查点；改用其他模型应标为方法迁移。

本次查阅的[DeepSeek官方API模型列表](https://api-docs.deepseek.com/quick_start/pricing/)列出的是V4系列服务，未列出论文中的R1-Distill-Llama-8B，不能直接用其官方API报价为该原模型复现计价。

建议暂不租 GPU或购买大额 API 套餐，先核实候选接口，再进行少量验证。若核心能力缺失，采用单卡 Qwen3-4B 的有限复现。

## 为什么看到 API key 不代表核心实验通过 API 运行

[官方 README](https://github.com/sudoparsa/CoDE-Stop/tree/b5081e7c2abe23bb1d19649421cc13522fee7c50)中的 API key 用于部分基准的答案判分。[models.py](https://github.com/sudoparsa/CoDE-Stop/blob/b5081e7c2abe23bb1d19649421cc13522fee7c50/models.py)通过 Transformers 加载权重，默认 CUDA 或 CPU；[method_codestop.py](https://github.com/sudoparsa/CoDE-Stop/blob/b5081e7c2abe23bb1d19649421cc13522fee7c50/method_codestop.py)直接执行模型前向、读取概率并管理缓存。

官方没有可直接替换的 API 推理后端，也没有现成的 Apple MPS/MLX 路径。Mac 调用远端 API 与 Mac 本地运行模型权重是两件事，后者需要另行评估内存与适配工作。

## API 能力验收

| 要求 | 原因 |
| --- | --- |
| 精确模型、精度、tokenizer 和聊天模板可核实 | 名称相似、量化版本或服务商更新后的权重不自动等价。 |
| 完整原始推理输出 | 需要定位检查点；只有最终答案或推理摘要不够。 |
| 从未完成的 assistant 推理前缀直接续写 | 检查点要插入试答提示；把此前推理放到新的用户消息中会改变条件。 |
| 贪心试答的逐 token logprob 与边界 | 置信度来自实际生成概率，不能替换为模型口头报告“有90%把握”。 |
| 长度、采样参数、停止规则可控 | 基础生成预算为32,768个新token，最终答案生成也需对齐。 |

试答 logprob 必须对应原实现未经温度或截断改变的概率分布；服务商仅在最终答案区域返回概率，未必覆盖原方法在思考前缀内插入的试答。要核实这些功能能同时使用，不能只检查参数名是否存在。

不一定需要完整词表 logits 或显式 KV 缓存接口：可靠的贪心生成 token 概率原则上足够；无缓存接口时可重发完整前缀，但输入费用和耗时会增加。其他基线可能要求额外能力，不能由 CoDE 可行推断整套基线均可行。

例如，[硅基流动的前缀补全说明](https://docs.siliconflow.cn/docs/userguide/guides/prefix)记录了对应参数，但该文档本身不足以证明特定原模型同时支持推理区间续写及所需 logprob。本文没有确认该平台已兼容。

## 单卡费用估算

依据[论文v2实验设置与表1](https://arxiv.org/html/2604.04930v2)，每模型基础轨迹数量为：AIME 900、MATH500 1,000、GSM8K 1,319、GPQA-Diamond 990，合计4,209；另有AMC校准。多种方法可以共享基础轨迹，不能按方法数量机械重复计算。

按论文取整的 Vanilla 输出均值推算，Qwen3-4B 在 MATH500 的基础输出约为 `1,000 × 5,210 = 5,210,000` token，四基准约32,385,654 token。

以下采用用户此前提供的 **6.98元/小时**。**50和100 token/s只是吞吐假设，不是实测**，指全任务的合计有效输出速度。

| Qwen3-4B 范围 | 基础输出 | 假设100 token/s | 假设50 token/s |
| --- | ---: | ---: | ---: |
| MATH500，每题2次 | 约521万token | 14.5小时 / 101元 | 28.9小时 / 202元 |
| 四个主要基准 | 约3,239万token | 90.0小时 / 628元 | 179.9小时 / 1,256元 |

这仅是基础解码费用折算，不含前缀计算、AMC校准、中途试答、最终答案、缓存搬运、初始化、判分等待、重试和存储。官方复现先生成完整轨迹，再回放并试答；论文报告的 token 成本不等于真实租卡费用。

若仅为观察开销敏感性，人为设定 Vanilla+DEER+CoDE 总运行时长为基础解码的 **1.5–3倍**，MATH500场景约152–606元，4B四基准约942–3,768元。这个倍数不是实测，也不是可靠上下界，实际可能超出。

建议若采用GPU，先设置 **50–100元诊断预算上限**，测各阶段时间和失败率；单模型MATH500首轮比较可暂留 **300–800元**。后一个金额只是预算安排，不能保证完成。原先500–1,000元应优先保障单模型单基准及复核，不承诺覆盖全文。其他模型尤其14B不能套用4B吞吐，全文总价目前缺少依据。

## API 费用估算方法

费用按百万token计：

`总价 = 未缓存输入量 × 输入单价 + 缓存输入量 × 缓存单价 + 输出量 × 输出单价 + 其他费用`

MATH500基础输出约521万token，因此仅该项为 `5.21 × 每百万输出token价格`。还需计入题目、反复提交的前缀、试答、最终答案、校准和判分。

量级示例：假设每条轨迹检查5次，每次平均重发2,500 token，1,000条轨迹就需 `1,000 × 5 × 2,500 = 12,500,000`，即 **1,250万输入token/一种停止策略**。这是说明重复输入影响的假设，不是论文实测次数。实际受检查频率、停止位置与缓存复用影响；多个策略也可能共享相同试答。

所以API可能省钱，但不能只算基础输出，更不能套用不兼容模型的低价。用户已明确目标模型，尚未选定服务平台；在功能及单价确定前，不给出虚构的API总价。

## 下一步与报告边界

1. 核对候选服务的模型版本、完整推理、精确前缀续写、试答logprob、采样和停止规则。
2. 用极少量非正式评测题验证能力组合，保存原始返回和计费字段，再实现适配层及固定前缀的后端对照。
3. 验证通过后做小规模诊断，以实测输入、输出、重试和耗时外推预算；未通过则回到单卡有限复现。
4. 换模型或改成普通黑盒策略，必须单独标记为迁移实验；原代码与论文公式差异仍依复现要求文档处理。
5. token节省、实际账单和延迟分别报告。API的排队、网络、缓存与硬件不同，不能将其请求延迟直接称为原论文同硬件上的加速比。
