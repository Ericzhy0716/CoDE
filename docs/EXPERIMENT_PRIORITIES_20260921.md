# CoDE-Stop：有限预算下的必要实验与可推迟项目

日期：2026-09-21。本文是执行优先级建议，未启动GPU或API实验。目标是先得到可信的复现子集，再判断有没有值得继续的研究问题；不是先复刻全文，也不把复现加小改动视为投稿贡献。

## 1. 当前必须保留的工作

| 项目 | 最小范围 | 用途与通过条件 |
| --- | --- | --- |
| 论文—代码一致性审计 | 本地手算置信度/退化分数/停止点，固定代码、模型、提示、预算和判分版本 | 现有公式、示例参数、短输出数值边界存在差异，须先记录并处理；修复不是创新 |
| 运行与资源诊断 | Qwen3-4B，先10–20条开发轨迹，补充长上下文/上限边界检查 | 检查完整答案、解析、显存、探测耗时、可续跑与记录完整性；该数目只作排错，不能证明性能 |
| 小规模价值诊断 | 50–100道独立开发题 | 同一批轨迹比较Vanilla、DEER、CoDE及调好的简单长度/步数截断；先验证是否有解释清楚的改进空间 |
| 有边界的正式复现 | 上述检查通过后，Qwen3-4B、MATH500、500题×2次、32K上限 | 比较Vanilla/DEER/CoDE，报告偏差、异常、准确率与总token；不能用几道题或短预算冒充论文子集 |
| 统计与错误核验 | 复用已有输出，尽量在Mac完成 | 成对正确→错误、错误→正确、停止原因、截断/漏答/解析失败；按题配对bootstrap，不把同题rollout当独立题 |

开发题必须与AMC校准题、最终测试题按题去重，同题不同rollout不能拆到两侧。可从另行固定的数学开发来源选50–100题，确认与MATH500/AMC无重复；本文件不假定已准备这些题。

若先用论文公布参数重跑，可以暂不重做AMC23，只报告“固定已发表参数的复现”。要调新方法、声称阈值迁移或重新完成校准流程，则需要独立校准，原论文AMC23为40题×2次。不能为贴近论文数字反复在MATH500选阈值；若用测试结果设计了新规则，应如实记录适应性使用，并安排未参与开发的确认性评估。

简单截断必须保留同样的最终答案生成机会。对照的固定长度/步数及阈值在开发/校准集选择，和新方法使用相同调参额度；需要多个提前设定的操作点比较准确率—成本曲线，不能只挑单个有利阈值。仅节省输出token并不足以证明时延或租金节省。

## 2. 有候选新方法后，支持论文主张的必要补充

以下是根据主张选择的证据，不是会议规定的固定实验数量，也不保证录用。

| 希望支持的主张 | 必需的确认实验 | 可以怎样控制成本 |
| --- | --- | --- |
| 优于原CoDE且不是简单调参 | Vanilla、DEER、CoDE、调好的简单截断/固定检查安排、新方法；补最直接的近邻方法 | 先固定一个主模型/基准；不能因对照贵就保留明显偏弱的设置 |
| 在不同推理情境仍有效 | 主基准外增加一个预先选定的、更难或不同任务类型的完整基准 | 当前默认优先AIME2024+2025；若主张跨领域则GPQA更相关。不可看到结果后只保留有利基准 |
| 不只适用于一个模型 | 第二模型，优先不同家族的DeepSeek-R1-Distill-Llama-8B | 先做独立开发诊断，再完成预定测试；不用立即补14B和Nemotron |
| 某个新设计是收益来源 | 删除/替换该设计的2–3个针对性消融，以及成本或正确率相当的简单替代 | 优先回放已有、信息充分的探测缓存；新增检查点和最终答案可能仍需补算 |
| 真正加速在线推理/降低部署成本 | 在线完整生成到最终答案的测时，包含检查、探测、缓存搬运与补答 | 先用预定代表子集，同卡/精度/批量/预算、预热、重复计时；报告范围和不确定性，不能把回放时间当在线收益 |
| 普遍稳定、收益可靠 | 成对区间、独立采样确认，必要时扩充样本 | 先做低成本统计；当结论受采样波动影响时再追加有针对性的生成 |

MATH500适合作为复现起点，但论文Qwen4B Vanilla准确率已为94%，单凭这里的微小变化不能充分支持“识别无效长推理”等广泛主张。AIME虽只有60题，原采样为每题15次，且推理长，不能因题数少就视为便宜。诊断时可减少采样，但应标为缩减实验，不与完整协议结果混称。

对近期最相关的方法作定向对照，而不要求所有文献全量复现。例如，如果做学习型停止或探测调度，需认真处理LearnStop及相应近邻；仅与较早DEER比较通常不能回答新颖性与竞争力问题。EAT等可在首轮排错时推迟，正式比较时按最终主张和最近邻选择，不能预先永久排除。

**当前建议的确认目标**是Qwen4B与DeepSeek8B、MATH500与AIME的两模型两基准矩阵，并配必要对照、核心消融和统计。它是有初步证据后再投入的规划；若只完成一个模型或一个任务，应相应收窄论文主张，不能用这个数量作为“达到顶会标准”的判断。

## 3. 当前可省略或推迟的实验

| 项目 | 当前决定 | 何时需要补回 |
| --- | --- | --- |
| 四模型×四基准全矩阵 | 推迟 | 主张广泛泛化或核心结果已经稳定、资源允许 |
| Qwen3-14B、Nemotron8B | 推迟 | 需要模型规模规律/第三家族证据 |
| GSM8K | 首轮可省 | 需要简单题上无伤害、跨难度规律或相应主张 |
| GPQA | 默认先推迟 | 声称跨领域/科学推理泛化时应补，不能仅凭数学结果推断 |
| Budget Forcing、CoD、NoThinking提示组合 | 省略首轮 | 新方法主张对提示策略通用 |
| 16K与32K全部预算重跑 | 首轮保留32K | 主张跨最大推理预算稳定时补另一预算 |
| Wait与Alternatively等所有分隔词 | 省略首轮 | 修改/依赖检查点或主张分隔词无关时补 |
| 复刻原文全部权重函数/退化指标消融 | 省略 | 与自己的核心机制直接相关时定向补 |
| 大规模网格搜索和所有配置重复多seed | 推迟 | 小范围校准或统计表明确有需要；不减少必要确认性重复 |
| LoRA、全量训练、RL、额外预测器 | 不启动 | 提出必须训练才能检验的新假设且先有价值证据 |
| 每个阈值重生整批完整推理 | 避免 | 新提示/模型/采样配置改变，或所需轨迹/试答缓存缺失 |

共享探测缓存必须验证模型版本、精度、token IDs、提示、停止边界和置信度计算一致。未来答案、完整轨迹标签可用于诊断，但不得作为实际在线策略输入；oracle只能标为上限分析。

## 4. 下一步与停止条件

1. 本地先完成公式与配置差异表、独立开发/校准/测试划分、日志与预算记录；不为准备文档持续开GPU。
2. 一张卡做小规模运行检查，再做50–100道开发题的价值诊断；不直接启动双模型四基准。
3. 若正确性完整、开销可接受，完成单模型MATH500复现。只有出现明确候选假设，才进入新方法确认矩阵。
4. 若收益来自漏记探测开销、没有输出答案、解析失败、实现错误或测试集调参，先修正；修正后再决定。
5. 若调好的简单截断/固定安排取得相同权衡，或收益小于当前不确定性，则不立即扩大模型/数据集，更不以补大表代替研究问题。先在开发集定位原因或重新选择问题。

## 6. 先4090诊断，再按需迁移5090

用户提出的分阶段租卡方案可行：4090 24GB可先尝试Qwen3-4B BF16、batch=1的流程与短输出诊断；是否能运行完整32K协议，取决于长前缀探测的实测显存峰值。少题数只减少总运行量，不降低单条最长样本的显存。临时缩短输出预算的调试结果必须单独标记，不能并入论文32K复现。

若4090通过目标协议的长样本检查且费用/完成任务有优势，可以继续使用，不必因为进入正式阶段而自动升级。若出现显存不足、需要更大批量，或5090的实测速度能抵消时租差，再换卡；5090也不保证所有模型/最长样本可运行。

公开参考价4090为1.88元/小时、5090为2.78元/小时，等开机时间每小时差0.90元，10小时差9元；不能据此断言完成相同任务就省9元。两者均能运行时，5090吞吐超过4090约1.48倍才抵消其时租差，另需考虑迁移与准备开销。[AutoDL公开参考价格](https://www.autodl.com/)

迁移安排：

1. 优先选择同地区，代码/配置同步GitHub，模型、完整输出、试答记录和版本清单保存在数据盘并备份关键结果；原始权重与原始运行输出不上传Git。
2. 在任务边界保存已完成的样本并关停源实例。AutoDL同地区可使用“克隆实例”选择5090目标主机，**勾选同时拷贝数据盘**；只保存系统镜像不会自动包含数据盘。
3. 新实例核验文件数量、大小/校验和、模型分片、配置和进度，再恢复后续样本。未完成的单条生成通常要重跑，迁移不等于复制运行中的GPU进程或KV缓存。
4. 检查5090的驱动、PyTorch/CUDA构建与算子支持，不能假定4090环境镜像原样必能用。预先选兼容两代卡的环境可降低迁移成本。
5. 保留GPU型号和软件版本记录；相同seed跨GPU不保证逐token相同，先做少量输出/概率核验。正确性/缓存复用须保证相同协议并记录来源；方法时延对比在同一GPU及环境重测，不把4090基线耗时与5090新方法耗时直接比较。
6. 数据核验前不释放源实例；原实例关机后的存储计费按所选产品另核对。

平台依据：[同地区克隆与勾选数据盘](https://api.autodl.com/docs/migrate_instance_2/)、[跨地区与系统盘/数据盘迁移说明](https://api.autodl.com/docs/migrate_instance/)。以上是方案，没有创建、迁移或启动实例。
